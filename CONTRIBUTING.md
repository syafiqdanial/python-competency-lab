# Working Agreement

This is a personal learning repository, but changes follow a professional contribution workflow.

## Workflow

1. Select or create a GitHub issue.
2. Create a branch such as `beginner/task-tracker` or `fix/csv-validation`.
3. Add tests and implementation in focused commits.
4. Run all applicable quality commands.
5. Open a pull request linking the issue.
6. Record decisions, limitations, and verification in the pull request.
7. Merge only after checks pass.

## Commit messages

Use concise conventional subjects such as:

```text
feat: add JSON persistence to task tracker
test: cover malformed task records
refactor: separate parsing from report rendering
docs: add task tracker retrospective
```

## Definition of done

A project is complete when its acceptance criteria pass, tests cover meaningful failure cases, documentation allows a clean setup, and a retrospective records the strongest lesson and next improvement.
